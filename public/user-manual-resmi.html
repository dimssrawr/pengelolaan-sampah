Tentang Panduan Ini

Petunjuk penggunaan aplikasi ini dibuat agar user (baik Warga Masyarakat umum maupun Petugas/Administrator Sistem) dapat mengoperasikan aplikasi Sistem Informasi Pengelolaan Sampah Terpadu (EcoResik) sesuai dengan prosedur yang telah ditetapkan sehingga maksud dan tujuan dari sistem ini tercapai.

Aplikasi EcoResik dirancang untuk mewujudkan pencatatan, pelaporan, dan pengelolaan data timbulan sampah berbasis web secara akurat, transparan, dan terintegrasi dengan basis data relasional PostgreSQL. Melalui buku panduan ini, pengguna dibimbing mulai dari proses registrasi akun, autentikasi multi-role, pelaporan sampah berfoto, verifikasi oleh administrator, manajemen master data, hingga pengujian relasi basis data One-to-One, One-to-Many, Many-to-Many, serta transaksi atomik (ACID).

1 Pendahuluan

1.1 Tujuan Pembuatan Dokumen

Dokumen petunjuk penggunaan aplikasi (user manual) ini dibuat dengan tujuan untuk memberikan gambaran dan panduan menyeluruh bagi user dalam menjalankan Sistem Informasi Pengelolaan Sampah Terpadu (EcoResik) secara maksimal kepada user. Dengan dapat dioperasikannya aplikasi ini, diharapkan koordinasi pengangkutan sampah, pelaporan dari masyarakat, pemantauan wilayah, dan validasi data oleh petugas dinas kebersihan dapat berlangsung lebih cepat, transparan, dan tepat sasaran.

1.2 Deskripsi Umum Sistem

Aplikasi EcoResik merupakan sistem informasi tata kelola sampah berbasis web modern yang dibangun dengan Next.js, TypeScript, Prisma ORM, dan basis data PostgreSQL. Sistem ini mengintegrasikan seluruh aktor pengelola sampah, mulai dari warga masyarakat yang melaporkan temuan sampah, petugas kebersihan lapangan, bank sampah, hingga administrator dinas. Sistem didesain mematuhi integritas referensial basis data relasional (UUID Primary Key, Unique NIK/Email, Foreign Key Restrict, dan Cascade Delete) serta menjamin keandalan transaksi atomik (ACID).

1.3 Deskripsi Dokumen

Dokumen ini berisikan informasi sebagai berikut:

  1. Pendahuluan
    Berisi informasi umum yang meliputi tujuan pembuatan dokumen, deskripsi umum sistem, dan deskripsi dokumen.
  2. Kebutuhan Sumber Daya
    Berisikan informasi perangkat yang dibutuhkan untuk mengoperasikan Sistem Informasi Pengelolaan Sampah Terpadu (EcoResik), meliputi perangkat lunak dan perangkat keras.
  3. Memulai Aplikasi
    Berisikan informasi yang menjelaskan langkah-langkah akses web, registrasi warga, dan login multi-role.
  4. Menu Portal Laporan Warga
    Berisikan tata cara input data pelaporan sampah berfoto (1:1) dan manajemen data laporan bagi masyarakat.
  5. Menu Portal Administrator
    Berisikan panduan monitoring seluruh wilayah, verifikasi laporan, dan pengelolaan master jenis & wilayah.
  6. Menu Inspeksi Relasi Database & Transaksi
    Berisikan dokumentasi skema ERD 10 model (1:1, 1:N, N:N) dan pengujian transaksi ACID.

2 Kebutuhan Sumber Daya

2.1 Perangkat Lunak Pendukung (Software Requirement)

Kebutuhan perangkat lunak (software) yang digunakan untuk dapat mengakses Aplikasi EcoResik adalah:

  1. Sistem Operasi (Operating System (OS))
    • Komputer / Laptop: Windows 7, Windows 8, Windows 10, Windows 11, macOS, atau Linux.
    • Smartphone: Android OS v8.0+ atau iOS 13+.
  2. Komponen Peramban Web (Web Browser)
    • Google Chrome (direkomendasikan versi terbaru).
    • Microsoft Edge, Mozilla Firefox, Opera, atau Safari.

2.2 Perangkat Keras Pendukung (Hardware Requirement)

Kebutuhan perangkat keras (hardware) minimum yang digunakan untuk dapat mengakses Aplikasi EcoResik adalah:

  1. Prosesor : Dual Core 1.8 GHz atau lebih tinggi
  2. Kapasitas RAM : 2 GB (disarankan 4 GB untuk performa optimal)
  3. Ruang Penyimpanan (Storage) : Tersisa minimum 500 MB pada perangkat pengguna
  4. Monitor / Layar : Resolusi minimum 1280 x 720 piksel (responsif pada layar ponsel)

2.3 Jaringan Internet (Internet Network)

Diperlukan jaringan internet untuk mengakses aplikasi ini secara daring, dan perlu diperhatikan kebutuhan akses jaringan internet sebagai berikut:

  1. Bandwidth Minimum : 256 Kbps (disarankan > 1 Mbps untuk pengunggahan foto bukti)
  2. Akses Internet : Koneksi WiFi, Hotspot Seluler, LAN, atau Kuota Data Seluler 3G/4G/5G
  3. Akan lebih baik jika latensi jaringan stabil demi kelancaran pengunggahan data secara *real-time*.

2.4 Sumber Daya Manusia

Sumber daya manusia yang direkomendasikan untuk mengoperasikan aplikasi ini adalah:

  1. Terbiasa bekerja dengan menggunakan perangkat komputer atau telepon genggam pintar (smartphone),
  2. Terbiasa menggunakan aplikasi berbasis Website dan formulir online,
  3. Mampu mengambil dokumentasi foto lapangan dengan jelas menggunakan kamera HP.

4.2 Formulir Pelaporan Sampah (Relasi 1:1)

Tata cara pengisian formulir pelaporan sampah oleh warga dijelaskan pada tabel berikut:

Item Keterangan
Berat Sampah (KG) Masukkan perkiraan bobot sampah dalam satuan kilogram (angka desimal > 0 kg, misal: 4.5 atau 12.3). Validasi sistem menolak input 0 atau negatif.
Jenis Sampah (FK) Pilih kategori sampah dari dropdown list: Organik, Anorganik, B3, Kertas & Karton, atau Plastik Daur Ulang. Terhubung sebagai Foreign Key.
Wilayah (FK) Pilih zonasi lokasi penemuan sampah dari dropdown list (misal: Kecamatan Kebayoran Baru, Menteng, Tebet). Terhubung sebagai Foreign Key.
Foto Bukti (1-TO-1) Klik tombol Choose File untuk memilih file foto sampah (JPG/PNG). Foto ini terikat secara ketat 1-to-1 dengan catatan laporan.
Tombol Kirim Laporan Klik tombol hijau Kirim Laporan untuk memproses penyimpanan transaksi ke basis data.

4.3 Manajemen Riwayat Laporan (Fitur Cascade Delete)

Warga dapat mengelola daftar laporannya melalui tombol aksi pada tabel "Daftar Laporan Sampah Saya":

  • Sunting Laporan (Ikon Pensil Hijau): Mengisi kembali form sebelah kiri dengan data yang ada untuk melakukan pembaharuan data berat atau wilayah.
  • Hapus Laporan (Ikon Tempat Sampah Merah): Menghapus laporan dari sistem. Berkat batasan basis data ON DELETE CASCADE, saat laporan dihapus, entri foto bukti pada tabel FotoSampah dan file fisik pada server otomatis ikut terhapus bersih tanpa menyisakan sampah data (orphan records).

6.2 Relasi One-to-One (1:1): LaporanSampah ↔ FotoSampah

Setiap 1 (satu) laporan sampah memiliki tepat 1 (satu) foto dokumentasi fisik. Kolom laporanId pada tabel FotoSampah berstatus UNIQUE dan NOT NULL, sehingga mustahil terdapat laporan yang memiliki foto ganda atau foto tanpa kepemilikan laporan.

Gambar 9. Diagram Relasi One-to-One (1:1) pada pgAdmin

6.3 Relasi One-to-Many (1:N): User ↔ LaporanSampah

Setiap 1 (satu) akun warga dapat membuat banyak laporan sampah seiring waktu, namun setiap baris laporan sampah hanya dimiliki oleh tepat 1 (satu) akun pelapor melalui Foreign Key userId.

Gambar 10. Diagram Relasi One-to-Many (1:N) pada pgAdmin

6.4 Relasi Many-to-Many (N:N): Petugas ↔ Jadwal

Relasi banyak-ke-banyak dimodelkan melalui tabel perantara (junction table) bernama PetugasJadwal dengan Composite Primary Key (petugasId, jadwalId). Satu petugas dapat bertugas di banyak jadwal, dan satu jadwal pengangkutan melibatkan banyak personil kebersihan.

Gambar 11. Diagram Relasi Many-to-Many (N:N) pada pgAdmin

6.5 Pengujian Transaksi Basis Data ACID

Pada rute /relasi, pengguna dapat menguji eksekusi transaksi atomik basis data. Sistem menjamin jika terjadi kegagalan saat pengunggahan foto, seluruh operasi dibatalkan (ROLLBACK) tanpa menyisakan catatan sampah pada basis data.
